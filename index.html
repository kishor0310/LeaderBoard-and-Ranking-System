Order Statistics & Fenwick Tree (Binary Indexed Tree)

How MNCs like HackerRank and PUBG query exact ranks among millions of scores in strictly $O(\log M)$ time.

Point Update: O(log M) Prefix/Suffix Query: O(log M) Space: O(M)

1. The Problem with Sorting

Sorting 1,000,000 players takes $O(N \log N) \approx 20,000,000$ operations. Running this on every live kill or solved problem kills CPU performance.

2. The Augmented Tree Approach

An Order Statistics Tree stores subtree sizes in each node. `rank(x) = 1 + rightSubtreeSize + parentAncestors` in $O(\log N)$ time.

3. The Fenwick / BIT Secret

Discretize scores into buckets (0 to 10,000). To find rank of score $S$: `rank = 1 + querySum(S + 1, MAX_SCORE)`. Updates take just 14 bitwise jumps!
